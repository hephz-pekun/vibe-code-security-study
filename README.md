# Does How You Prompt Change How Secure Vibe-Coded Software Is?

Term project for *Securing AI and Security with AI* (Howard University, Fall 2026).
Author: Iyanuoluwa Hephzibah Olanipekun

This repository holds the prompts, AI-generated code, analysis scripts, and results for a small empirical study of whether the way a developer prompts an AI coding assistant changes the security of the code it writes.

> **Warning:** the code in `outputs/` was generated by AI assistants and left unreviewed on purpose. It contains known and suspected vulnerabilities (hardcoded secrets, open redirects, debug servers, and others). **Do not deploy it.** `scripts/smoke_test.py` executes this code, so run it only in a throwaway environment.

## What was studied

16 realistic Flask/SQLite application tasks (`tasks/`) were given to three free AI assistants (Claude Sonnet 5.5, Gemini 4 Hydrogen, Microsoft Copilot Chat) under these conditions:

| Condition | Workflow | Files |
|---|---|---|
| C0 | Plain prompt | 48 (tasks 1-16) |
| C1 | Plain prompt + one OWASP-style security sentence (`tasks/C1_suffix.txt`) | 48 (tasks 1-16) |
| C2 | Scan the C0 code with Bandit and Semgrep, feed findings back to the model to fix | 24 (tasks 1-8) |
| C4 | Same scan-and-fix step applied to the C1 code | 24 (tasks 1-8) |
| C3 | A different model reviews the code, the author patches it | not run (`scripts/build_c3.py` included, unused) |

All 144 programs were scanned with Bandit 1.9.4 and Semgrep 1.185.0 (Python 3.14.2), with suppression comments disabled. Prompts were run manually in free web chat interfaces, one fresh chat per task, model, and condition.

## Headline results

Same eight tasks, three models, 24 files per condition, four noisy rules excluded (see the paper):

| Condition | Bandit findings per file | Semgrep findings per file |
|---|---|---|
| C0 plain | 0.58 | 0.92 |
| C1 security prompt | 0.54 | 0.29 |
| C2 scan-and-fix | 0.25 | 0.38 |
| C4 prompt + scan-and-fix | 0.25 | 0.00 |

Most of the raw gap between C0 and C1 comes from a single setting (Flask debug mode: 28 findings under C0, none under C1). A manual check of 25 findings found 14 were false alarms, so these are scanner counts, not confirmed vulnerabilities. See the paper for caveats.


## Reproducing the analysis

From the repository root, in PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install bandit semgrep flask pillow beautifulsoup4 argon2-cffi flask-wtf flask-sqlalchemy bcrypt requests

# scan everything and print the comparison tables
python scripts\analyze.py --ignore-nosec
python scripts\analyze.py --ignore-nosec --exclude-rules B201 debug-enabled render-template-string avoid_hardcoded_config_TESTING

# build the scan-and-fix prompts
python scripts\build_c2.py                                # C2: fix the C0 files
python scripts\build_c2.py --source C1 --target C4        # C4: fix the C1 files

# minimal functional check (executes the generated code)
python scripts\smoke_test.py
```

Run the plain `analyze.py` last if you want `results/findings.csv` to include every rule. Semgrep may need `--semgrep-config p/python` if `--config auto` fails. Generation itself was manual, so the prompts in `tasks/` can be pasted into any assistant to extend the study.

## Limitations

Small sample (8 to 24 files per cell), scanner-based measurement with a high false-positive rate, unpinned model versions in free chat interfaces, and a minimal functional test (the home page returns a non-500 status). Patterns here motivate larger studies and are not statistical claims.
